# 读者常驻运行时

命定之诗由自动正则直接托管读者，非命定之诗可使用独立常驻脚本（见下方「运行方式」），都与消息显示分开。ES 模块导出 `start()` 和 `stop()`；启动后复用原悬浮信封，不需要夜梦先发言。停止或切换聊天会清理旧控制器、音频、浮层、观察器及事件订阅。同一聊天的消息更新、候选切换和正则重绘保留控制器与播放器。

```powershell
node tools/build_core.mjs
node --test tests/runtime.browser.test.mjs
```

构建产物：

- `dist/reader-runtime.js`：自包含 ES 模块，一次装载原有菜单、人格、唱片机、书架、模板等功能。
- `dist/reader-card-runtime.js`：命定之诗使用的自包含模块，含卡内默认运行时及本地版本选择入口；不自动检查更新或安装脚本。
- `regex/读者对话渲染-脚本版.json`：轻量信件，仅含外观、正文和常驻应用的调用桥，没有音频元素、完整应用或网络加载器。
- `dist/core-build.json`：运行时和信件的字节数及 SHA-256。

`tools/build_core.mjs` 也导出 `build({write:false})`，返回 `{rules,runtime,cardRuntime,sizes}`，只使用 Node 标准库。集成仓可受控复制 `source/` 中的文本源码和构建器，不依赖相邻开发目录。

## 源码

- `legacy-reader.js/css`、`legacy-body.html`：从既有发布版提取的可维护功能源码。
- `core-runtime.mjs`：单实例入口、宿主 API 桥、聊天生命周期与轻信登记。
- `controller-prelude.js`：观察器、Worker、宿主监听及节点资源的清理。
- `controller-adapter.js`：复用原有功能，将消息所属逻辑改为控制器所属；音频焦点及书海窗口接入。
- `letter.js`、`letter-body.html`：轻信展示和点击桥。
- `reader-transactions.js`：固定聊天、楼层、候选的状态提交及去重。
- `booksea-host.js`：按需装载并保留书海窗口，收起时保留游玩现场。
- `template-system.js`：原内嵌压缩模块的可维护源码。
- `booksea-album.js`：书海第六专辑的 124 首曲目、reader 自托管的六首替换曲目，以及单曲校验、加载和回收。
- `reader-gacha.js`：大厅「命运抽卡」面板（`window.ReaderGacha`）。由 `gacha/` 打包生成，见下方「命运抽卡」，不要手改。

## 悬浮信封

沿用原来的 `dfb` 信封外观、拖动与位置，不再创建单独的「读者」按钮。彩蛋服务的「隐藏常驻悬浮窗」默认为关闭，保存于 `dream_hide_persistent_float`。

| 显示模式 | 隐藏常驻悬浮窗 | 行为 |
| --- | --- | --- |
| 默认 | 关闭 | 常显信封，点击直接进入大厅 |
| 默认 | 开启 | 不显示悬浮窗，从嵌入正文的信封进入大厅 |
| 悬浮 | 关闭 | 常显信封；最新楼层有信先看信，否则进入大厅 |
| 悬浮 | 开启 | 最新楼层有信才显示信封，否则隐藏 |

最新楼层取聊天实际末条消息，旧楼层的信不补位；候选切换和编辑会使旧信件登记失效。同层多封信按正文标签顺序显示。读信窗与大厅相互切换时关闭前一个窗口，悬浮模式隐藏嵌入信件，切回默认模式恢复。

升级前已经显示的完整版信封也接入同一个大厅和设置，不必等消息重新渲染。隐藏常驻悬浮窗后，仍可从正文信封进入彩蛋服务恢复；悬浮模式下，这些旧信封也按当前楼层、候选和正文内容登记来信。

## 命运抽卡

大厅三套主题（咖啡馆、盛夏、水墨）与纸笺菜单里的「命运抽卡」直接打开抽卡面板，旧的“抽卡5次”点单已经撤掉（不再往输入框写字）。面板配色跟随当前大厅主题：咖啡馆是深色木纹与黄铜，盛夏是海盐玻璃与天蓝，水墨是纸笺与青瓷；抽卡舞台三套都是夜色（暖夜、深海、墨夜）。

1. 选文学或 ACGN 与主题（内置 39 个，可自定义），**换大池**：从 Bangumi、AniList、VNDB、Wikidata、Open Library 等公开资料库随机捞起 99 部作品。花 1000 命运点，捞到作品之后才扣；一部也没捞到、取消或扣点失败都不扣，也不换掉当前这片书海。按钮要点两次才生效。
2. 挑一部作为**小池**：查 Bangumi 角色、维基剧情章节与 Fandom 设定页，由夜梦编纂小池（品质用命定之诗的 普通～神话，角色为唯一）：合计 54～99 张，物品与命运各有多少、品质怎么分配都由模型按作品决定，物品里至少 9 件神话，命运至少一张神话。物品类型包括武器、防具、饰品、消耗品、材料、资产、技能书页、信物、文书等。编纂分几次请求：先规划张数并写物品，再写命运（打开角色池时再写角色），最后按**世界观物品生成细则**写物品属性（见下），每次最多等 5 分钟；某种卡没写成或写得不够时用资料直出的卡补足，回复被截断时取出其中完整的卡。没有可用的独立生成时整份用资料直出（物品 30 件含 9 件神话、命运 24 张）。换了大池要重新挑小池，编纂过的小池留在这台设备的缓存里；旧版（物品与命运各 18 张）的小池缓存不再使用，要重新编纂。
3. **世界观物品生成细则**（抽卡设置，默认开启）：编纂的最后一步经酒馆助手读当前角色卡（主、附加）、聊天与全局世界书里名称包含设置里条目名的条目（默认「技能装备道具生成规则」「品质效果限定」「核心数值表」「状态规则」；每个名字取一条，启用的优先，去掉 EJS 等模板语法），让模型照条目里的格式与品质区间给装备、武器、消耗品、资产等写出类型、标签与“效果名: 效果”，每 12 件一次请求。入包时这些物品直接带着格式化的属性，无需二次激活。技能书页、命运与角色书页不写：它们在正文里使用时由正文模型按规则生成完整属性（技能书页可以转赠）。细则不内置在脚本里，玩家改了世界书里的规则也照新的写；读不到条目或某一批没写成时，那些物品照旧只写大概，并在编纂步骤里说明。条目名可在设置里改。
4. **角色池**（抽卡设置，默认关闭）：打开后小池在物品、命运之外再加上角色，三者合计仍是 54～99 张，分配由模型决定，不强制均分。角色全部是**唯一**品质，出货率与神话相同（0.3%），同一部作品里抽到过的角色不会再出现：抽到的名字记在 `dream_gacha.uniques`，主角背包里还留着的这部作品的角色书页也算抽到过；都抽到后，唯一那一份按比例分给其余品质。抽到的角色以书页的形式由主角持有（背包类型「角色书页」，名字前缀「角色·」，效果写明身份、定位、实力“完全等同原作”与具现规则）；一旦被选择具现，便在完全保有自身自由意志的情况下自由行动，主角无法强制约束。资料直出时只用资料里真有的人物，不凑数；旧缓存里分星级的角色读出来也是唯一。打开开关之前编纂的小池要重新编纂才有角色。
5. **混池单抽 200、十连 2000**：物品、命运（打开角色池时还有角色）混在一个池子里抽，不能指定只抽哪一种；面板里的物品 / 命运 / 角色标签只用来翻看池内的卡。神话基础 0.3%，120 抽内必出一张随机神话（小保底，没有逐抽提高；唯一不算神话、不清小保底；换小池、换大池都不清零）；十连至少一张稀有。**大保底**：在一部作品的小池里每抽攒 1 点抽取点数（只记在这部作品上），攒满 200 点可兑换这部作品小池里任选的一张神话；点数只能在这部作品的小池里使用，不跨池互通，换大池也不清零。兑换不花命运点、不动小保底：先在 `dream_gacha` 扣点，再经 `ReaderTransactions` 入包，入包失败把点数退回。
6. **回收**：主角背包里来自命运抽卡（标签首项「命运抽卡」）的东西可以按品质换回命运点数，每件是与同一层级的角色缔结命定契约基础价的 1/25：普通 8 · 优良 20 · 稀有 100 · 史诗 200 · 传说 2000 · 神话 6000 · 唯一 6000。可以整档回收、回收 1 件或全部，都要点两次。角色书页也一样，回收掉的唯一角色不会再抽到。按现行概率，抽一次平均只能回收约 115，把大保底兑换的神话也算上约 145（一直有唯一可抽时约 165），抽了再回收换不回本。别处来的物品不收。

界面只显示命定之诗的品质名，原来的“只显示星级”选项已撤掉：背包不会把星级映射回命定之诗品质，留着只会出错。入包时也不再写「星级:」标签。以后通用化读者核心时再按宿主加回品质刻度。

- 定价是固定的，面板设置里只能决定抽到的东西是否放进背包（关闭后照样扣点，只记在抽卡记录里）。
- 换大池、抽卡与回收都走 `ReaderTransactions`：固定当前聊天、最新楼层与候选，一次变量提交（回执 `:gacha-cast`、`:gacha`、`:gacha-spark`、`:gacha-recycle`），与读者其他付费操作互斥；点数不足、聊天或候选变化、背包里的东西变了时什么也不写。入包物品同名不同物时加作品名区分，不覆盖原有物品。
- 书海旅程未结束时不换大池、不抽卡、不回收（那段时间的命运点数与背包由书海结算）：按最新楼层的书海进度引用找到存档判断，旧存档看聊天镜像。
- 保底、各作品的抽取点数（最多 200 部）、各作品抽到过的唯一角色与最近 100 次记录保存在聊天变量 `dream_gacha`。99 部作品、小池（含写好的物品属性）与览概缓存（按聊天分开，留最近 6 个聊天）和设置（含角色池开关与细则条目名）保存在这台设备（`dream_gacha_device_v1`、`dream_gacha_settings_v1`）。
- 编纂小池与补写中文览概经酒馆助手 `generateRaw`，走「独立API」里的「命运抽卡」路由。资料库请求从这台设备的浏览器直接发出，不带聊天或角色内容；跨域被拦时可经酒馆 `/proxy/` 重试。
- 面板美术来自读者：当前外观的立绘、头像场景与当前大厅主题的抽卡小人。面板盖在大厅之上；脚本版经登记文档创建，停止读者或切换聊天时与控制器一起清理，完整版在信件页面卸下时撤掉。

脚本版把 `source/reader-gacha.js` 放进常驻控制器（在 `ReaderTransactions` 之后），完整版与外链版由 `tools/build_release.py` 放在主脚本里同样的位置。完整版的整段 HTML 是酒馆正则的替换文本，所以打包结果里不能有 `$` 加数字、`$<名字>`、`{{match}}`，也不能有酒馆宏或 `</script`，打包脚本与构建脚本都会检查。

源码在 `gacha/`（TypeScript）：`src/gacha/` 是规则、资料库、小池、背包与回收、服务层，`src/ui/` 是面板、样式与矢量美术，`src/reader/` 是读者端口与 `window.ReaderGacha` 入口。改完重新打包并构建：

```powershell
cd gacha
npm install
npm test
npm run build
cd ..
node tools/build_core.mjs
python tools/build_release.py source/读者对话渲染.json
```

`gacha/tests/gacha.test.ts` 覆盖概率与大小保底、唯一、经济（回收换不回本）、资料库映射、小池规划/解析/截断/补足、资料直出、混池与唯一角色、世界观物品生成细则、大保底兑换与退回、换大池扣点、回收与读者端口；`tests/gacha.test.mjs` 用真实 `ReaderTransactions` 检查扣点入包、角色书页与兑换回执、换大池、回收与聊天切换，并核对大厅入口与完整版构建；`tests/gacha.browser.test.mjs` 在 Chromium 运行实际构建，从大厅打开面板直到换大池、十连写入与回收。

## 宿主接口

`window.ReaderCore` 提供 `open('lobby')`、`close()`、`openBooksea(action)`、`setAudioFocus('reader'|'booksea')`、`ready` 和 `stop()`。控制器内的 `window.ReaderGacha` 提供 `open(host)`、`close()`、`isOpen()`、`price()`（换大池、单抽、十连的命运点数）与 `dispose()`，由大厅的命运抽卡调用。轻信通过 `registerLetter()` 登记展示，不写 MVU。`openBooksea` 支持 `maze/narrative/descend/leave`，供书海标签打开同一游玩实例。开发联调可用 `window.ReaderCoreConfig.bookseaBase` 指定书海资源根。

浏览器回归在本机存在 Chrome 和工作区 `playwright-core` 时运行；其他环境显式标记跳过。它检查无来信菜单、六信共用应用、同一音频跨消息重绘继续播放、真实聊天切换、停止清理、初始化中停止、部分初始化失败后重试、旧异步调用隔离，以及停止后重启时现存轻信的重新登记。不会发起付费模型请求。

## 运行方式

正则统一为「读者对话渲染-脚本版」，只含信件外观、正文和调用桥，不运行播放器或完整菜单。

命定之诗使用 `dist/reader-card-runtime.js`，由自动正则的既有 `start({base})` / `stop()` 生命周期托管。它包含卡内默认读者，**不创建独立脚本库条目**，不改通用自动正则或其他核心。

- 正常启动只读一次 `dream_reader_hosted_runtime_selected_v1` 小记录。没有手动选择时直接运行卡内默认模块；有更新的已选版本时从本地 CacheStorage 取回并校验，以 Blob 模块运行。不查询最新版、更新清单或发布证明，不重新下载运行时，不增加轮询。
- 同页重复消息、编辑、候选切换不再读选择或导入模块，也不重建播放器。停止始终作用于实际运行模块，恢复过程中停止不会产生迟到实例。
- 用户在「检查更新」确认后，沿原签名与摘要链下载，再把源码保存到独立 CacheStorage；约几百字节的选择记录只在保存和读回核对成功后写入。成功后清理上一选择的旧源码，不把数 MB 内容放进 localStorage。
- 保存成功显示「下次启动读者时生效」；当前菜单和音乐保持原样。刷新酒馆或重新启用该核心后使用已选版本。新卡自带版本更新时不会回退到更旧的本地选择。
- 缓存不存在、损坏或不可用时提示并使用卡内版本，不为了恢复而联网。浏览器清理缓存后手动更新的选择需要重新确认；缓存 API 不可用时拒绝保存更新，保留旧选择。

`source/card-host.mjs` 管理托管入口、启动取消和手动选择；`source/hosted-runtime-store.js` 只管理本地存取，无联网或定时器。默认模块延迟初始化；选中缓存版时不会另建一份默认控制器。

不使用命定之诗自动正则的玩家仍可使用独立脚本。旧外链版、固定版首次迁移时，在原正则的角色或全局范围安装「读者常驻脚本」，保存并就绪后换成轻量信件；后续更新写回同一脚本条目。预设范围暂不迁移。

已手动启用独立脚本的玩家保留原方式，托管入口不会抢占或改写脚本库。若要完全使用自动正则托管，停用原独立脚本后重新载入核心。旧版命定之诗程序资源没有本地托管入口，主卡4.4前使用下述临时兼容，不会自动创建独立脚本。

### 主卡4.3临时兼容

适用于用户提供的「【命定之诗】自动正则」加载器（默认程序资源 `1.2.2`）。它加载的卡内读者为 `2026.10.31.1`，提供 `replaceRuntime()`，没有新版 `hostMode: "auto-regex"` 本地托管接口。

手动检查只比较版本；确认更新后，沿用签名发行、固定清单和 SHA-256 校验链下载 `reader-runtime.js`，把发行身份写入旧键 `dream_reader_core_selected_v1`，再立即热替读者，播放会中断。失败恢复原选择记录；不会安装脚本库条目。启动恢复仅重新验证并载入上次确认的同一运行脚本，不查询最新版、不更新轻量正则或世界书。聊天变化、实例接管、固定来源不符或更新选择变化时不会让旧恢复覆盖当前状态。

此兼容仅调整 reader；没有修改主卡或书海。旧 CDN 默认模块是固定资源，仍会在刷新后先启动，再通过上述旧键联网恢复所选版本，无法仅靠 reader 改成本地离线启动。新版托管入口仍由 `card-host.mjs` 保存缓存、下次启动生效；独立脚本仍使用脚本库更新。

首次接入：本地补丁需要作为新的 reader 正式版本发布，旧卡默认读者原有的更新入口才能取得它。若已经选中过显示「等待主卡4.4」的 reader 版本，单纯刷新仍会恢复那个旧版本；需先备份旧选择记录，再回到卡内默认读者的更新入口，手动检查并确认修复版。仅在本地构建不会改变玩家已经运行的代码。

撤销：将 `source/update-center.js` 的 `LEGACY_CARD_UPDATES` 改为 `false`，重新构建并以新 reader 版本发布；旧宿主恢复原「等待主卡4.4」状态。`TEMP_MAIN_CARD_43` 标记集中列出临时代码，也可在撤销时移除相关分支、适配器恢复调用和兼容测试。不要提前删除旧选择键，否则仍使用旧 CDN 默认入口的玩家会失去已确认版本；主卡4.4托管入口不读取这个键。

## 统一更新

菜单只保留「检查更新」。正则、常驻脚本和世界书分别比较已安装版本与签名发布版本，仅更新过旧项目；世界书先执行，脚本最后替换。签名固定正则只作为数据读取，以其源提交和清单摘要验证 `reader-runtime.js`、`reader-letter.json` 及世界书资源，下载的完整版加载器不会装入脚本版。

集成宿主可通过 `start({base,updates:{installRegex}})` 提供轻量信件的安装回调，回调收到已经过签名链与 SHA-256 验证的 `{version,metadata,release,regex}`；未提供时使用独立安全替换路径。托管宿主额外提供 `hostMode: "auto-regex"`、`installRuntime(artifact, guard)` 和 `getHostedRuntimeState()`；更新页显示实际运行版本与已保存待生效版本。独立脚本仍经脚本库更新。

固定版升级到脚本版时，会把同版、完整的 ES 模块与启动入口保存为酒馆助手脚本库中的「读者常驻脚本」。安装范围沿用原正则的角色或全局范围；核对后端保存结果并等待控制器就绪后，才将完整版正则换成轻量信件。脚本下载或启动失败时保留完整版；脚本库总开关关闭时会提示开启对应范围后重试。预设范围暂时保留完整版，避免不能核实保存结果的迁移。后续独立脚本更新同样写回脚本库，刷新后继续使用已安装版本。

`standalone-bootstrap.js` 管理脚本库入口的核心与聊天生命周期；`script-installer.js` 负责脚本条目保存、后端读回和就绪核对；`fixed-migration.js` 负责首次迁移。新固定版清单的 `installMode: "script"` 表示用户已选择该脚本版本，加载后完成这个版本的首次迁移，不查询或自动同意其他新版。

固定版身份按检查时已验证的发行标记和原规则 ID 核对，支持导入后保留的旧 ID。每次重新检查都重新识别当前运行方式；独立脚本同时核对脚本库、后端保存及实际实例的就绪状态。历史提交或失败记录仅在这次核对确认同版或更新版本已生效后改为完成。并发迁移只有在整组正则完全符合已验证的目标、脚本已保存并就绪时才认作已完成，不覆盖玩家后续编辑。

正则更新只把被替换的那几条旧规则存进浏览器（`dream_fixed_update_receipt_v1`、`dream_reader_fixed_migration_backup_v1`、`dream_reader_light_backup_v1`），以前整份保存各范围全部正则，会撑满酒馆共用的 5 MB 存储。旧版本留下的大备份只在用户检查或更新时缩成同样的内容，不在普通启动时额外读取。存储仍然写不进时照常更新，并在结果里说明备份未保存；旧固定版可从发布页重新下载。

构建可显式指定版本：`node tools/build_core.mjs 2026.10.29.1`；其后兼容发布构建会把轻量正则和常驻脚本加入发布清单，固定版构建验证全部清单文件。

脚本版的同一更新页也检查已安装的书海固定版。只有书海过旧时只更新书海；两份正则都过旧时先验证全部资源，再按范围合并保存。集成宿主可提供 `installRegexBatch` 回调，在原有正则读回、缓存维护流程中调用请求的 `commit()`；旧宿主缺少此能力时会明确提示升级，不会把未执行的书海更新报告为成功。
