# 读者固定版

现有「读者对话渲染-外链版」继续跟随作者更新。「读者对话渲染-固定版」使用独立的稳定正则 ID，安装时停用外链版，避免同时渲染同一条信件。

固定版正则内置数字版本、完整源提交 SHA，以及 `fixed-release-manifest.json` 的 SHA-256。根清单固定 CSS、正文模板、兼容脚本、常驻运行时、轻量正则与 `gallery/`、`personas/`、`worldbook/`、`vendor/` 的资源哈希。运行镜像使用相同的完整提交 SHA，下载和缓存均重新校验 SHA-256；离线时仅使用该版本且校验成功的缓存。资源缺失、校验失败或版本不存在时保留信件原文并允许重试，不转用 `main` 或最新版。局域网 HTTP 没有 Web Crypto 时使用内置 SHA-256，仍验证完整内容。

## 玩家如何升级

保留当前版本时不需要操作。在「彩蛋服务台 → 检查更新」中对比读者、书海两份已安装固定正则与静态更新清单中的数字版本。检查会验证 GitHub 签发的发布证明。没有新版本时显示没有可用更新；断网、清单或证明异常时显示检查失败，不能据此判断已是最新。

点击「更新可用项目」后，按世界书、正则、常驻脚本的顺序逐项执行。每项在写入或执行前完成其全部下载和验证，单项失败会保留实际结果，其他可用项仍可继续。正则更新需要酒馆助手 4.9.3 或更新版；替换前核对原始范围，助手不能完整保留的设置会拒绝自动更新。保留原启用状态、匹配规则、深度和顺序，保存更新前的备份；脚本版只更新轻信，不安装完整版加载器。世界书更新先保留旧条目，写入失败恢复旧条目。常驻脚本由原宿主更换模块，独立运行时也支持替换，并使旧模块的停止接口继续回收新实例。

也可手动编辑正则替换内容中的 `const VERSION="2026.10.27.5"`，只修改引号内的数字。与内置版本相同时直接使用内嵌固定信息；改成其他数字时，从静态清单取得该版本的 GitHub 发布证明，验证证明和固定附件后，读取附件中的源提交与根清单哈希。该过程只把新版正则作为数据读取，不执行下载到的加载器。版本不存在或校验失败时明确报错，不改用其他版本。

已同意的常驻脚本版本会保存固定版本记录。旧集成包刷新后只尝试恢复这个已同意版本，重新验证发布证明及资源哈希；断网时保留当前已装运行时，并在检查页明确显示尚未恢复，不查询或自动同意其他新版。

检查更新和切换到其他版本均不需要玩家的 GitHub token 或账号登录，也不调用 GitHub REST API。正常刷新不查询最新版，不额外预加载相册、字体或棋引擎，也不下载发布证明验证模块。固定运行资源按需读取；书海的大资源按内容哈希验证和复用，相同整包不会仅因数字版本变化而重复下载。

锁定范围是作者管理的程序及仓库内的配套内容。按作者选择，字体与棋引擎继续使用原先第三方来源；第三方图片、音乐和外部 CG 的目标内容仍由原站提供，固定的是本版的链接列表。用户聊天、存档与自行配置的 API 不被版本锁定。

## 静态清单与发布证明

每个仓库的 `fixed-updates` 分支只存放更新数据：`index.json` 列出数字版本，`releases/v<版本>.json` 保存 GitHub 原始签名证明。客户端使用固定的仓库和路径，通过 raw/jsDelivr 获取这些文件，不接受清单提供的任意下载地址。清单不作为代码执行，也不能自行决定某份附件的可信摘要。

浏览器使用 `tools/release-verifier` 中的官方 sigstore-go 验证逻辑离线验证 Sigstore DSSE 发布证明。验证器的运行脚本和 WASM 只在检查或切换版本时按需下载；其完整提交 SHA、内容 SHA-256 和大小固定在本版代码中，验证成功后才运行。正常打开当前固定版本不加载验证器。

验证从客户端内置的 GitHub TUF 信任种子开始。`trust.json` 镜像 GitHub 官方签名元数据链及 `trusted_root`；每日 Actions 和发布器刷新镜像，客户端验证签名、信任根轮换和有效期。不能仅凭镜像里的自声明密钥建立信任。元数据过期、签名无效或轮换链不完整时检查失败，不跳过验证，也不降级到旧证明来声称已是最新。

发布证明必须由 GitHub 发布服务签发；验证包含证书身份、证书链和签名时间戳。签名内容绑定仓库名称、owner ID、repository ID、数字版本标签、分发提交 D 与固定正则附件 SHA-256。下载附件时使用证明中的摘要校验；附件本身包含源提交 C 和根清单摘要，后续程序及资源再按根清单验证。附件跨域下载受限时，raw/CDN 回退使用证明中的完整 D 提交，而非可移动分支。

作者改动静态清单或证明镜像，不能为已签发的同一固定版本替换附件内容。证明只说明发布内容由 GitHub 固定，并不证明新版本代码没有恶意行为；确认更新仍是对该版本代码的新一次信任。静态清单也不能证明作者没有隐瞒更新，缓存可能暂时延迟新版出现。本机记录最高已验证版本以拒绝清单回退；此记录不能证明绝对最新，清除浏览器存储后也不会保留。

## 作者构建

保留现有 `tools/build_release.py` 的外链版流程。完整源正则和常驻运行时构建时装入五个本地模块：

- `source/fixed-release-client.js`：静态清单、发布证明与附件验证、软件 SHA-256。
- `source/fixed-runtime.js`：固定版的二级资源读取。
- `source/regex-update-guard.js`：检查助手能否完整保留其他正则的设置。
- `source/release-updates.js`：固定版正则扫描、安全替换及更新记录。
- `source/update-center.js`：唯一更新页面、三个组件协调、失败隔离及已选择版本恢复。

以 `2026.10.27.5` 为例：

```powershell
node tools/build_core.mjs 2026.10.27.5
python tools/build_release.py source/读者对话渲染.json 2026.10.27.5
python tools/build_fixed_release.py 2026.10.27.5 --prepare-manifest
npm test
git add source tools tests docs dist regex release-manifest.json fixed-release-manifest.json
git commit -m "Prepare reader fixed release 2026.10.27.5"
git rev-parse HEAD
```

最后输出的完整 SHA 为源提交 **C**。发布正则必须从 C 内的清单与资产生成，构建器逐一检查字节数和 SHA-256，不采用未提交工作区里的同名资源。准备清单后若修改任何脚本或资源，需要重新构建、准备清单并重新提交。

```powershell
python tools/build_fixed_release.py 2026.10.27.5 <完整C提交SHA>
```

生成的稳定附件名为 `regex/reader-fixed.regex.json`。HTML 中保留机器可读的 `FIXED_RELEASE` 标记；正则宿主即使移除 JSON 顶层的额外属性，更新检查仍可识别已安装版本。

## 打包与发布

GitHub 仓库须先启用不可变 Releases。普通分支、普通 tag 或版本目录都可被作者覆盖，不能单独提供相同保证。发布脚本通过官方接口预检仓库设置；该作者端预检需要仓库管理读取权限，不属于玩家的更新请求，也不替代客户端签名验证。

先在本地打包供检查：

```powershell
python tools/publish_fixed_release.py 2026.10.27.5 <完整C提交SHA>
```

默认只在 `.runtime/fixed-release/reader-v2026.10.27.5/` 创建 detached worktree 和分发提交 **D**，输出附件路径、哈希、C/D SHA；不会推送或发布，也不会移动当前分支。D 以 C 为父提交，只增加生成的固定正则。`v2026.10.27.5` 指向 D，正则内部仍锁定 C，避免提交引用自己的 SHA。Release 附件与 D 中的正则字节完全相同。

准备正式发布时使用新的本地打包目录并显式传入 `--publish`：

```powershell
python tools/publish_fixed_release.py 2026.10.27.5 <完整C提交SHA> --directory .runtime/fixed-release/reader-v2026.10.27.5-publish --publish
```

脚本预检设置、远端仓库和版本不存在后，推送指向 D 的新 tag，创建草稿、上传附件并核对 GitHub 返回的 SHA-256，再正式发布并确认不可变状态。GitHub 在正式发布后生成签名证明；发布器随后获取证明、刷新官方信任材料并更新 `fixed-updates` 清单。证明就绪之前不把版本加入清单。作者端需要发布权限，玩家端不需要凭据。

禁止覆盖已有 tag、Release 或附件。发布之前失败时保留可检查的本地结果或草稿，先核对实际状态再继续。若 Release 已正式发布，只是证明或清单更新失败，应重试补齐该版本的清单，不重建或覆盖版本：

```powershell
python tools/publish_update_catalog.py Adirm007/reader 2026.10.27.5 --publish
```

也可单独刷新官方签名信任材料：

```powershell
python tools/publish_update_catalog.py Adirm007/reader --refresh-trust --publish
```

修复已经发布的代码必须使用新的数字版本。若要让外链版同步此次代码，正常推送源码分支 C；固定发行 tag 和更新清单分支不替代源码分支。

## 验证

资源测试覆盖根清单替换、等长脚本篡改、缓存损坏、离线加载、跨版本缓存隔离、无 Web Crypto 的完整校验、同源提交镜像、手动数字版本切换，以及源提交 C 与分发提交 D 的字节一致性。更新测试覆盖静态清单格式、最新版本证明失败、附件摘要不符、已见版本回退和先完成全部校验再写入；发布证明验证器另有真实证明与篡改输入测试。
