# 2026.11.12.2 酒馆默认移动样式下的书海窗口高度

用户在 2026.11.12.1 发布后反馈手机仍只显示顶部细条。本次用酒馆 `public/index.html` 的完整样式栈复现，而非仅用无宿主样式的浏览器页面。

## 确定根因

酒馆默认 `public/style.css:143–147` 给 `html` 设置 `translateZ(0)` 与 `perspective`，使根元素成为固定定位窗口的包含块；`public/css/mobile-styles.css:250–254` 则在手机布局下令 `body` 固定定位。body 脱离文档流后，html 自动高度实际为 0px。

书海窗口原先只设置 top/bottom，没有明确 height。这些边距相对于零高的 html 解析，普通外壳仅剩 2px 边框，新外壳仅剩 10px 内边距，游戏 iframe 均为 0px。正常 41px 或 80px 输入栏也能触发，和输入区是否过高无关。

单变量反证：仅将 body 恢复为静态定位、仅取消 html 的 transform 与 perspective，或仅为书海设置明确高度，都会恢复窗口。前两项只用于验证，没有修改玩家的宿主样式。

## 改动

`source/booksea-host.js` 直接设置窗口高度为可视视口高度减去上下边距，同时设 bottom:auto 与 box-sizing:border-box。沿用既有视口、旋转、输入栏避让及全屏还原逻辑，不增加回退分支，不更改信封、全屏方式、书海游戏或存档。

上次验证的错误在于：构造了输入区挤压的另一种场景，却没有加载用户实际使用的酒馆移动样式。因此 2026.11.12.1 的测试通过不能证明真实反馈已修复。新增回归直接锁住上述宿主 CSS 组合，修复前四组全部失败。

## 验证

- 最小回归保留正常输入栏，覆盖新旧外壳、390×844 和 844×390、全屏还原及旋转；明确断言宿主 html 仍为 0px，游戏窗口仍可用。
- 独立验证加载酒馆 public/index.html 的全部真实 CSS、完整 ReaderCore 与书海 0.47.0 原始发行资源。新旧外壳与横竖屏四组均恢复，宿主 CSS 保持原样。新版横屏 iframe 从 0px 恢复至 790×308，入口全屏为 814×332，还原为 790×308；竖屏为 336×678。
- 资源管理按钮通过实际命中及触摸点击打开和关闭，零脚本错误。截图和几何结果保存在本地 `.runtime/mobile-booksea-qa/host-css-final*`。
- 最终完整回归 339/339 通过，0 失败、0 跳过。全宿主样式与真实书海资源的四场景 36/36 通过；独立显示探针补验 320px 窄屏、常规手机与桌面，共 32/32 通过。

使用 Chromium 移动视口与触摸模拟；没有连接反馈用户的手机，不将这些结果称为真机验证。书海继续使用 0.47.0。
