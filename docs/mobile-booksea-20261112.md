# 2026.11.12.1 书海移动端入口修复

> 后续更正：本版没有修复用户实际酒馆默认移动样式下的问题。原测试遗漏宿主 CSS，输入区挤压只是另一个可触发场景。真实根因与补修见 [2026.11.12.2](mobile-booksea-host-css-20261112.md)。

用户反馈手机书海只显示顶部细条，通常从读者进入。实际入口为 `controller-adapter.js` → `createReaderBookseaHost` → 书海 `bootPersistent`。

## 根因与修复

`source/booksea-host.js` 原先优先读取 `#form_sheld` 的顶部作为底部避让边界。移动主题将这个包装层撑到屏幕上方时，即使实际 `#send_form` 仍只有 80px，书海也会被挤扁。真实 Chromium 的 390×844 视口下，旧外壳仅高 4px，新外壳仅高 10px，两者游戏 iframe 都为 0px。书海内部跟随 iframe 高度布局，所以只剩顶部边线。

修复优先测量实际输入栏，并在输入区占用过高时回到屏幕边距，保证游戏区域可用。用户确认手机横屏游玩，因此短视口也优先保留游戏高度，不再固定为输入栏留出 96px。窗口使用宿主 `visualViewport` 的尺寸和偏移，保留安全区域；普通、全屏、还原及隐藏后复开使用同一布局计算。监听输入栏尺寸、窗口方向及可视视口变化，重试和销毁时清理监听及观察器。

本次修改读者入口，书海 0.47.0 会随 iframe 自动调整，无需改动其资源、游戏规则或存档。

## 验证

- 浏览器回归覆盖新旧外壳、390×844 与 844×390、异常包装层、正常输入栏避让、键盘缩小视口、全屏及还原；旧代码四组异常包装层用例均失败，修后通过。
- 真实读者运行时从彩蛋服务台点击进入，加载书海 0.47.0 正式分发和界面资源。四组游戏 iframe 从 0px 恢复为：新版竖屏 678px、横屏 308px；旧版竖屏 690px、横屏 320px。资源准备页正常启动，无脚本错误。横屏下载按钮在右书页内滚动后可达；分别用鼠标滚轮和原生触摸拖动、点击验证，资源管理、全屏还原、旋转及隐藏复开通过。
- 验证使用 Chromium 移动视口和模拟酒馆接口；软键盘通过视口变化验证，未冒充 iOS/Android 真机、真实聊天或完整 Godot 游玩验收。截图和机器结果位于本地 `.runtime/mobile-booksea-qa/`。
- 最终 `npm test` 335/335 通过，0 失败、0 跳过；UI 类型检查通过。另用本地 Godot/PCK、合成队伍及真实书海战斗组件，从完整读者菜单进入横屏，8/8 检查通过：舞台 790×308、技能列表滚动、触摸预览/确认技能、选敌施放、全屏 332px 及还原 308px，零浏览器或 Godot 脚本错误。信封保持原有行为，验证中仅通过现有触摸拖拽把它移到空白处。

按用户最终要求，不改悬浮信封或现有全屏方式。本次仅发布移动布局修复。
